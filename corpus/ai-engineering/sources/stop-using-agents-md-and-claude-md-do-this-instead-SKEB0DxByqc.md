# Stop using AGENTS.md and CLAUDE.md (do this instead)

> **Source** (YouTube · ZazenCodes · 2026-03-30). [watch on YouTube](https://youtu.be/SKEB0DxByqc) · [transcript](../../../raw/youtube/youtube-SKEB0DxByqc-stop-using-agents-md-and-claude-md-do-this-instead.md)

**TL;DR:** A research paper titled *evaluatingagents.md — Are Repository-Level Context Files Helpful for Coding Agents?* (available on arXiv) found that developer-written context files improved coding-agent performance by ~4%, while LLM-generated ones *decreased* performance. Both variants inflated inference costs by ~20%. Practical recommendation: keep context files minimal, agent-specific, and non-redundant with the README.

---

## What are repo-level context files?

`CLAUDE.md` (Anthropic/Claude Code) and `AGENTS.md` (OpenAI/Codex) are files placed in a repository specifically for coding agents to read at the start of every task session.[^1] They are interoperable — any coding agent can consume either naming convention.[^1] A minimal example covers tech-stack choice and a few conventions (e.g., "This app uses React and TypeScript, prefer small components").[^1] When generated automatically via `claude /init` or equivalent, they tend to become verbose and duplicate information already in the README.[^1]

---

## The research

Paper: *evaluatingagents.md — Are Repository-Level Context Files Helpful for Coding Agents?* (arXiv, free PDF).[^1]

**Three experimental conditions** tested across multiple real repositories:[^1]

| Condition | Description |
|---|---|
| Developer-written | Human author wrote the context file specifically for that repo |
| LLM-generated | Auto-generated by a coding agent (`/init` or equivalent) |
| None | No context file at all |

**Benchmarks used:** SWE-bench Light (300 tasks) and AgentBench.[^1] For AgentBench all three conditions were tested; SWE-bench only compared None vs. LLM-generated.[^1]

**Models evaluated:** Claude Code (Sonnet 4.5), OpenAI Codex (GPT), and a Qwen model — "very modern stuff, very recent as of March 2026."[^1]

**Evaluation protocol:** Each agent was given a task description derived from a real issue or pull request, a repository state before the fix, and evaluated by whether its generated patch made the test suite pass.[^1]

---

## Results

- **Developer-written** context files improved task-success rate by **~4%**.[^1]
- **LLM-generated** context files *decreased* performance on average (effect sizes of 0.5–2%, but consistent across ~4,000 samples, so statistically meaningful).[^1]
- Both conditions **increased inference costs by ~20%**, because the file is loaded into context at the start of every agent session.[^1]

The speaker notes the absolute deltas are small but that the direction matters: "it's notably different than the increase in performance from the developer-written context file."[^1]

---

## Practical recommendations

Derived partly from the paper, partly from the speaker's interpretation (noted explicitly in the source).[^1]

**Include:**
- Minimal, agent-specific instructions that would never go in a README — e.g., "don't run tests yourself; give me test-run instructions instead."[^1]
- Tooling constraints and agent-behavior guardrails.

**Avoid or prune:**
- Auto-generated context files, or at least heavily prune them before use.[^1]
- Redundancy with the README — "you might not need that as well in the clod file."[^1]
- Verbose repository overviews for standard repos where directory names are self-descriptive — agents can `ls` and infer structure directly.[^1]
- Extra micro-instructions that increase agent work without improving success rate.[^1]

**Alternative:** instruct the agent to read the README at the top of the context file (`"read the readme file"`) rather than duplicating its content.[^1]

---

## Demo summary

Speaker implemented a newsletter block on the homepage of zazencodes.com using Claude Code twice: once with the auto-generated `CLAUDE.md` (cost $0.10), once without it (cost $0.07).[^1] The agent without the context file explored the repo via file-listing and found the newsletter route itself — behavior the `CLAUDE.md` did not noticeably shortcut.[^1] Speaker concluded the demo is anecdotal ("it could have gone either way") and the research results are the main signal.[^1]
